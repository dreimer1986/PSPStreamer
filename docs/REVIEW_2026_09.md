# Maintenance review, September 2026

Scope: current PSP playback, diagnostic hooks, settings, server routes,
offline transport, browser assets, and the independent overclock prototype.
This is a source/test review, not a certification that the project has no
remaining bugs or an on-device stability claim.

## Changes

- `debug=0` is the default for old/new configurations. GUI settings persist it.
  Diagnostic watchdogs, timestamp/copy measurements, reader snapshots and file
  writes are gated; informational decoder/profile/completion counters are
  hidden. Real error messages and recovery paths are not disabled.
  The SELECT+L+R component test card is available only with debug enabled.
- Watchdog startup is skipped entirely when debug is off. A read-only/full
  Memory Stick therefore cannot block streaming just because a diagnostic
  report cannot be created. Debug-on mode preserves its strict startup probe.
- Removed the synthetic sync media catalogue and calibration generator, not
  the PTS parser tests. Tests now generate fixtures outside production code.
- Root `server.py` contained an obsolete standalone implementation with an
  incorrect static path. It is now a four-line compatibility launcher.
- Removed unused old `static/app.js` from both deployments. The actual web UI
  is the inline script in `index.html` plus `offline.js`.
- Removed the client JPEG receiver and software-frame presentation blocks
  already excluded with `#if 0`; no active decoding path was removed.
- Media ID decoding now rejects negative/out-of-range root indices and
  malformed JSON types consistently instead of interpreting -1 as the last
  library root or returning an internal error.
- Native server shutdown now closes the offline queue on Ctrl+C.
- Corrected stale PCM wording; documented debug defaults and OC limitations.

## Deliberately unchanged

The proven audio buffer ownership, FLV container PTS, decoder module order,
LCD/TV framebuffer layout and network/subtitle startup budgets have not been
retuned. Diagnostic-free playback avoids additional timing queries and a
monitor thread, but no FPS/CPU improvement is claimed without measurement.
Legacy server H.264/subtitle frame-index endpoints remain compatibility paths;
their old rate constants do not clock current FLV/PTS playback. Removing them
would be a separate protocol compatibility change, not a synchronization fix.

The debug trace still reserves its bounded static RAM buffer even when disabled.
Changing allocation strategy while preserving the working decoder heap is not
part of this cleanup. Rendering instrumentation counters used by host tests
remain internal, with no debug display or logging while disabled.

HTTPS certificate-change notices and actual decoder/MilkDrop/network failures
are operational/security messages, not optional debug noise.

## Remaining risks / tests

- Hardware playback must still be tested with debug off/on, both LCD and TV,
  online and local files. Host tests cannot validate PSP DMA/ME behavior.
- ZIP copy must preserve the complete job folder; the ready marker is not a
  replacement for safe ejection or protection against later Memory Stick damage.
- CFW plugins can conflict. The independent OC plugin is disabled by default,
  restricts models, reports register-derived estimates, and rate-limits
  reapplication. It has no independent frequency measurement and cannot prove
  silicon stability. See its README before any activation. It does not patch
  app clock syscalls and cannot guarantee an uninterrupted forced frequency.
- OC snapshot writes and PLL transitions can cause stalls when requested.
  Test the plugin separately, after confirming the player-only build.

All server changes are mirrored into the Home Assistant app; ordinary Docker
uses the same Python/static sources. HA release is 0.1.32. No Docker/HA runtime
deployment is implied by source parity and host tests.
